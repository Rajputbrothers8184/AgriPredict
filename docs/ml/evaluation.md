## What the results show

**1. Horizon length dominates model choice.** XGBoost won **all six 7-day**
comparisons, but at **30 days the seasonal naive baseline won four of six**.
That is the expected behaviour of gradient-boosted trees: they cannot
extrapolate beyond the target range seen in training, so once the forecast walks
far enough past its training window its output flattens while the true series
keeps moving. Seasonal naive has no such failure mode.

**2. A better model is not automatically the right default at long horizons.**
This is why the service stores *both* artefacts and selects per horizon from the
recorded backtest winner rather than hard-coding "XGBoost everywhere".

**3. MASE values above 1 are reported, not hidden.** For wheat at 30 days even
the winner scores MASE 1.811, meaning it is *worse* than a naive seasonal repeat
on this series. Reporting that honestly is the point of using MASE.

**4. Year-over-year seasonal drift is the hard part.** The synthetic generator
gives each series a different annual phase; a model that latches onto a weekly
lag (XGBoost's top feature is `lag_7`) predictably does well at 7 days and less
well at 30.

## Methodology details

### Rolling-origin backtest

```
fold 0 : [---------- train ----------][-- test 30d --]
fold 1 : [----------- train -----------][-- test 30d --]
fold 2 : [------------ train ------------][-- test 30d --]
```

* Fold 0 always trains on ≥ 180 observations; folds advance by one test window.
* A model is re-fitted from scratch inside each fold on that fold's training
  window only.
* Evaluation is a **random-split-free** protocol: shuffling a time series would
  let the model train on the future, which is the single most common way
  forecasting results become unreproducible.

### Metrics

| Metric | Definition | Why it is here |
| --- | --- | --- |
| MAE | mean absolute error, PKR/40 kg | primary, interpretable to a farmer |
| RMSE | root mean squared error | penalises large misses (a bad forecast is costly) |
| MAPE | mean absolute percentage error | comparable across commodities at different price levels; `None` when any actual is 0, rather than dropping points |
| Bias | mean (predicted − actual) | exposes systematic over/under-prediction |
| MASE | MAE scaled by the seasonal-naive in-sample error | `>1` means the model loses to the naive benchmark |

### Feature set (XGBoost)

Lags 1, 2, 3, 7, 14, 28 · rolling mean/std/min/max over 7/14/30 days (shifted by
1) · 1/7/30-day differences and percentage changes · day-of-year, month,
day-of-week, month-start/end flags · sin/cos annual encoding. 30 features in
total. Every feature for day *t* uses only data up to *t*; the target is
`price[t+h]`, and a separate booster is trained per horizon so errors cannot
compound recursively.

## Reproducing this report

```bash
cd ml
pip install -r requirements.txt
python -m datasets.fixtures.generate_synthetic --out datasets/raw/synthetic.csv
python -m training.build_dataset --source datasets/raw/synthetic.csv
python -m training.train_all --folds 3        # writes reports/evaluation.{json,md}
python -m pytest tests -q                     # 85 tests
```

Wall-clock on a laptop CPU: dataset build < 1 s, training and evaluation ~24 s
for 6 series × 2 horizons × 2 models × 3 folds.

## Roadmap to real numbers

1. Obtain the AMIS Punjab daily price export (or PBS monthly series).
2. `python -m preprocessing.loaders --check <file>` — confirm the schema and,
   importantly, that prices are **PKR per 40 kg**.
3. `python -m training.build_dataset --source <file>` — inspect
   `datasets/processed/dataset_profile.json` for gaps and outliers.
4. `python -m training.train_all --folds 5` — 5 folds on 2+ years of daily data.
5. Replace this document's headline table with the real results, keeping the
   limitation section truthful about the data window used.
